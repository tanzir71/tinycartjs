SETUP - SHARED HOSTING

TinyCart Setup

A practical deployment path for shared-hosted storefronts that need PHP/SQLite checkout, COD collection, order operations, and a small cart UI.

CHECKLIST

Upload, configure, protect.

The basic install is flat files. The important work is tightening origins, secrets, product truth, payment methods, admin auth, and file permissions before real orders arrive.

01

Upload files

Put tinycart.js, checkout.php, optional endpoints, and these HTML docs into public_html/tinycart or your storefront directory.

02

Configure origins

Set ALLOWED_ORIGINS, endpoint-specific origin lists, API keys, product catalog rows, coupons, payment methods, credentials, and webhook secrets.

03

Protect data

Create a private writable data/ directory for SQLite, logs, rate-limit buckets, and queued webhook or analytics records.

Requirements

  • PHP 8.1 or newer is recommended.
  • pdo_sqlite and json are required. mbstring is recommended.
  • A writable private data/ folder is required for SQLite, logs, rate limits, and queues.
  • Use HTTPS before collecting real customer contact details or payment redirects.

Recommended file layout

Keep public endpoints in your storefront folder and protect the writable data directory. If your host allows private folders outside public_html, put data/ there and update the path constants.

Configure the PHP files

Edit checkout.php first. Keep PRODUCT_CATALOG and COUPONS as server truth. Configure ENABLED_PAYMENT_METHODS for choices such as online, COD, or manual payment. Then configure optional coupon.php, payment.php, catalog.php, admin.php, and collect.php only if your store uses those features.

ALLOWED_ORIGINS = ["https://store.example"]
API_KEYS = ["long-random-public-endpoint-key"]
HMAC_SECRET = "server-only-secret"
PAYMENT_PROVIDER = "stripe" // or "paypal", or blank
ENABLED_PAYMENT_METHODS = ["online", "cod"]

COD and ops dashboard

COD orders skip Stripe and PayPal, store payment_status as cod_due, and stay visible in admin.php until an operator marks cash collected. After setting admin auth, use the dashboard to filter orders, update payment and fulfilment status, edit stock, toggle coupon overrides, export CSV, and queue webhook retries.

  1. Filter for cod_due or new orders at the start of the day.
  2. Open each order detail, verify contact/address/items, and call or WhatsApp the customer when needed.
  3. Move fulfilment through confirmed, packed, shipped, and fulfilled.
  4. Press Cash collected only after cash is received.
  5. Export CSV after filtering the route, date, status, or payment method you want.

Go-live checks

Before switching traffic to real orders, complete one end-to-end pass for each enabled payment method.

  • Place a no-discount order and confirm the order row, line items, totals, and inventory decrement.
  • Preview a valid coupon through coupon.php, then complete checkout and confirm the stored discount.
  • Place a COD order and mark Cash collected in admin.
  • If online payments are enabled, verify the provider redirect and paid callback path with sandbox credentials.
  • Trigger a failed webhook once, then use Retry now after the receiver is healthy.
  • Download a CSV export and confirm formula-like customer cells are prefixed for spreadsheet safety.

Protect data and logs

On many cPanel accounts, 750 for directories and 640 for SQLite/log files is enough. Add a .htaccess file inside data/.

Require all denied

Top-level security headers should include a Content Security Policy with exact connect-src origins. Do not use wildcard CORS for checkout or analytics.

Troubleshooting

Origin errors

Use exact origins in every endpoint. https://store.example and https://www.store.example are different.

API key errors

If endpoint keys are configured, the widget must send the same public key through apiKey.

SQLite write failures

Check ownership and permissions for data/. Avoid world-writable folders.

Coupon drift

Keep COUPONS aligned in checkout.php and coupon.php, then check admin overrides.

Missing payment redirect

online requires PAYMENT_PROVIDER, provider credentials, and success/cancel URLs.

Webhook retries

Fix the downstream URL or signature handler first, then queue retry from Webhook health.

Common Node hosting

TinyCart itself is static. On Render, Railway, Fly.io, Vercel, Netlify, or a VPS, serve the client file and implement the same endpoint contract: exact origin checks, max body size, field validation, parameterized SQL, and rate limiting.
